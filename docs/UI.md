# 로컬 운용 UI

프로젝트 폴더에서 `python -m trendfollow ui --port 8765`를 실행하고 브라우저에서 `http://127.0.0.1:8765`에 접속한다. 별도 UI 패키지는 필요 없다. 포트가 사용 중이면 다른 포트를 지정한다. 서버 종료는 터미널의 Ctrl+C다.

화면 상단의 일봉 수집 원천 선택은 어느 화면의 데이터 갱신·일별 처리 버튼을 눌러도 적용되며 브라우저에 선택을 기억한다. 네이버와 pykrx 모두 일상적인 종가 처리에서는 기존 과거 일봉을 유지하고 새 거래일만 추가한다. 별도 `research-data` 명령은 연구 자료 전체를 다시 수집·게시하는 작업이다. pykrx는 `python -m pip install -e ".[krx]"`와 KRX 정보데이터시스템의 `KRX_ID`, `KRX_PW`가 필요하다. 프로젝트 루트 `.env`에 두 값을 입력하거나 UI 서버의 운영체제 환경변수로 지정한다. 환경변수가 `.env`보다 우선한다. 경계 날짜의 기존 가격·거래량과 새 원천 값 차이는 `manifest.json`의 `source_comparison`에 기록한다. KRX 자료는 수정주가와 시장 범위가 기존 원천·증권사와 다를 수 있으므로 기준 가격이 불일치하면 장중 판단은 보류된다.

관측 중에는 KIS 체결을 시간대별 잠정 가격·누적 거래량으로 요약한다. 각 시간대 종료 직전 60초 안에 새 체결이 없거나 연결이 끊기면 해당 시간대의 조건 판단을 보류한다. 이 기록은 확정 종가나 모의계좌 반영 자료가 아니다.

## 종가 처리와 장중 관측의 차이

**종가 처리**는 실행 버튼을 누르면 확정 일봉으로 조건을 자동 판단하고 로컬 모의 체결·현금·보유·매매 이력을 반영한다. 당일 처리는 16:10 이후 가능하다. 첫 처리는 종가 기준점과 다음 진입 계획만 만들며, 과거 장중 거래를 소급 체결하지 않는다. 이후 처리에서 기존 진입 계획과 보유 종목 조건을 모의 반영하고, 새 신호는 다음 거래일 계획으로 저장한다. 실제 다음 시가에 백그라운드 주문이 실행되는 구조는 아니다.

**장중 관측**은 ON 이후 직전 종가 계획과 실시간 시세로 잠정 조건을 판단해 관측 기록·신호를 남긴다. 모의 매수·매도나 현금·보유 변경은 하지 않는다. 장중 돌파가 종가에 사라지는 등 두 판단 결과가 다를 수 있다. 같은 데이터·설정·계좌 상태에서 장중 관측 여부 자체는 종가 모의성과에 반영되지 않는다.

**장중 관측은 종가 처리를 대체하지 않는다.** 관측만 한 날은 모의계좌 처리일이 진행되지 않으므로 장마감 후 종가 처리를 별도로 실행한다. 두 기능 모두 증권사 주문은 없으며 실행 버튼으로 시작한다. 정해진 시각의 예약 실행은 연결하지 않았다. 이 차이는 운용 순서 화면의 상시 안내와 장중 제어·모의 기록 화면에도 표시한다.

## 화면 기능

- **시장·후보**: RS 순위와 Mansfield 값, 선택 RS 조건, 산업 액션, 셋업, 거래량, 종가 진입 조건·계획 수량을 필터·검색한다. 최근 최대 180개 완료 일봉을 조회한다. 산업 표는 분석 후보별 판정 집계이며 산업 전체 상승 비율과는 구분한다.
- **신호·보유**: 다음 시가 진입·추가매수 계획, 보유 수량·공통 손절·3R, 청산 이벤트, 로컬 모의 체결·청산 손익을 확인한다.
- **운용 순서 1 · 계좌·설정**: RS/Mansfield, 초기 손절·폭 제한, 산업 조건, RS 청산, 시장 유닛, 추가매수·위험 예산을 설정한다. 전체 JSON도 편집할 수 있다. 저장하면 별도 설정과 미시작 비교 계좌가 생긴다. 기존 세 계좌를 덮어쓰지 않는다.

좌측 운용 계좌 목록은 계좌 이름과 함께 기본/일반/정정 비교 유형, 마지막 계좌 처리일(또는 미시작)을 표시한다. 일반·정정 비교 계좌는 `이 계좌 보관`으로 기본 목록에서 숨길 수 있다. 보관은 설정·일봉·모의 기록을 삭제하지 않으며 `보관 계좌 표시`를 켜서 조회하거나 `이 계좌 보관 해제`로 다시 기본 목록에 넣는다. 기본 계좌는 보관할 수 없고, 해당 계좌의 작업이 진행 중이거나 실행 여부가 미확인이면 보관을 보류한다. 정정 비교 계좌의 종목 차트는 그 계좌의 고정된 재계산 일봉을 사용한다.

좌측 `계좌 이름 변경`에서는 일반·정정 비교 계좌의 표시 이름만 바꾼다. 이름은 앞뒤 공백을 제외하고 1~60자이며 계좌 ID, 설정, 일봉, 처리일, 매매 기록과 보관 상태는 유지한다. 기본 계좌 이름은 변경할 수 없다.
- **운용 순서 4 · 장중 관측**: 종가 후보에서 종목을 지정해 다음 거래일 계획을 만든다. 해당 거래일의 KRX 정규장과 NXT 애프터마켓에 관측 시간을 정해 ON/OFF하고 종가 결과와 대조한다. 선택 계좌의 UI 관측 기록을 보여준다. 시장 유닛 등 기존 장중 엔진이 지원하지 않는 설정은 계획 생성 시 거절된다.
- **운용 검증**: 적용 설정, 위험·추가매수 검토 사유, 작업 성공·실패를 확인한다. 산업 자료 갱신, 종료된 장중 거래량 누적, 동시간 거래량 기준 생성을 실행한다. 최소 5개 유효 거래일이 필요하며 실제 준비 여부는 결과의 준비 구간 수로 확인한다. 생성한 기준은 이후 생성하는 계획부터 적용된다.

## 시장·후보 필터와 거래량 배수

선별 종목표 위에서 산업, RS 통과 여부, 산업 액션, 파동 단계, 셋업 조건, 최종 신호, 거래량 조건과 검색을 함께 선택한다. 조건은 AND로 적용되며 `필터 초기화`로 모두 해제한다. 산업 선택은 분류별 종목 선택이고 산업 액션은 동반 상승 판정이므로 서로 다른 조건이다. RS 통과는 선택 계좌의 RS/Mansfield 방식에 따른다. 파동 단계와 준비·돌파·무효화 판정은 서로 다른 축이므로 함께 선택할 수 있다. 선택한 셋업 조건의 기준과 가상 파동 그림은 필터 아래에 표시한다. 그림의 ④ `셋업 돌파`는 `셋업 조건 → 셋업 돌파`에 연결되고 `52주 신고가 → 돌파`와는 별개다. 그림의 구간을 클릭하거나 키보드로 선택하면 해당 필터와 종목 목록이 함께 바뀌고, 같은 구간을 다시 선택하면 해제된다. 그림 또는 메뉴에서 다른 파동 단계를 고르면 앞서 선택한 돌파 조건을 해제한다. 그림의 `파동 전체`는 파동 단계와 셋업 조건만 초기화하며 다른 필터는 유지한다. 그림은 실제 종목 시세가 아니다. 종목을 열면 실제 값과 계좌 기준을 함께 보여준다. 준비 조건 충족은 최종 진입 신호를 뜻하지 않는다. 미확인 값을 미통과로 취급하지 않으며 산업 액션 미적용도 별도로 선택한다.

필터는 선별 종목표만 변경한다. 상단 전체 후보 요약과 아래 산업 동반 상승 집계는 전체 분석 자료 기준이다. 매매 조건·계좌·감시 계획을 변경하지 않는다. `52주 신고가`는 오늘 종가가 직전 252거래일의 최고가보다 높은지 보여준다. 과거 252거래일이 부족하면 `자료 부족`으로 표시한다. 52주 필터를 선택한 경우에만 그 기준과 현재 계좌의 신호 반영 여부를 별도 설명으로 표시한다. 셋업 조건과 52주 필터를 함께 선택하면 표시 목록은 교집합(AND)이며 유효한 조합임을 명시한다. 반면 `파동 셋업에 52주 신고가 경로 추가`를 켠 계좌의 최종 매수 후보는 두 경로 중 하나가 통과해도 가능(OR)하며, 다른 공통 조건도 통과해야 한다. 조정·베이스와 당일 셋업 돌파, 최종 신호 통과와 RS 미통과처럼 규칙상 서로소인 필터 선택지는 비활성화하고 그 이유는 접힌 도움말에서 확인할 수 있다. 비활성화된 다른 선택지를 현재 필터 조합의 오류로 표시하지 않는다. 같은 날 결과가 0건이더라도 이론상 함께 성립할 수 있는 선택지는 유지한다. `새 계좌 만들기 · 전략 설정`에서 옵션을 켠 비교 계좌를 만들 수 있다. 이 설정을 켜지 않은 기존 계좌에는 52주 판정을 정보로만 보여준다.

선별 종목표의 `52주 신고가` 열은 종가와 직전 252거래일 최고 고가의 차이를 비율로 표시한다. 고가를 넘으면 빨간색 `돌파`, 아직 넘지 못하면 파란색 `남음`으로 표시한다. 해당 날짜의 감시 종목에 정상 수신된 KIS 체결과 장중 52주 고가 기준값이 모두 있으면 `현재가 · 잠정`으로 표시한다. 이때 장중 기준값에는 후보 기준일의 고가도 포함된다. 시세가 끊기거나 지연되면 저장된 `종가` 기준으로 돌아간다. 필터와 확정 신호는 저장된 종가 판정을 유지한다.

52주 항목이 도입되기 전에 저장된 후보 파일에는 해당 컬럼이 없다. 이 경우 화면 조회 시 계좌에 연결된 저장 일봉에서 직전 252개 고가를 읽어 표시값만 보완한다. 후보 파일과 모의계좌의 과거 판단은 변경하지 않는다.

시장 후보 화면에서 저장된 종가 분석 날짜를 선택해 당시 결과를 조회한다. 기준일 선택에는 최근 완료 거래일과 그 이전 거래일도 표시하며 시장 종목 선정 기록, 시장 후보 조건 계산 기록, 선택 계좌의 조건 계산 기록을 각각 구분한다. 같은 날짜에 시장·계좌 분석 기록이 모두 있으면 함께 표시한다. 정정 재계산 계좌에서는 고정된 계좌 처리일과 일별 처리 비활성화 이유를 화면 상단에 표시하고, 원계좌 이동 버튼을 강조한다. `시장 후보군 저장` 버튼은 후보 기준일 선택과 별도로 오늘 장 마감 후 KIS 종목 마스터를 읽어 시장 후보군을 날짜별 파일에 한 번만 저장하고 이전 저장일 대비 편입·제외 종목과 이유를 보여준다. 장중에는 이미 저장된 직전 완료 거래일 기록을 사용한다. 그 기록이 없으면 현재 마스터를 과거 날짜로 소급하지 않는다. 후보 상태 카드는 종가 기준 준비·저항선 접근(1 ATR 이내)·돌파·고가 접촉 후 종가 하회를 구분한다. KIS 관측 중에는 신선한 체결가와 관측한 저항선 접촉을 사용해 잠정 돌파·접촉 후 후퇴를 구분하며, 구독 거절·연결 준비/끊김·체결 없음·시세 지연·가격 기준 불일치는 각 사유로 표시한다.

종목 마스터는 KIS가 배포하는 코스피·코스닥 종목 목록과 상태 정보다. 종목코드·이름·시장·업종·거래정지·관리종목·기준가·전일 거래량 등을 담는다. 후보 기준일 메뉴의 `시장 종목 선정 기록 있음`은 날짜별 종목 목록이 저장된 상태이고, `시장 후보 조건 계산 기록 있음`은 그 목록 전체에 선택 계좌의 전략 조건을 평가한 상태다. `계좌 조건 계산 기록 있음`은 모의계좌의 저장된 분석 결과다. 시장·계좌 계산 기록은 별도로 저장되며 한쪽이 다른 쪽의 완료 단계를 뜻하지 않는다. 2026-11-08 마스터와 11월 10~13일 계좌 일봉이 있어도 그 사이의 전체 시장 편입·제외는 정확히 재현할 수 없다. 과거 날짜의 전체 시장 기록을 채우려면 그 날짜의 종목 마스터 등 당시 기준 자료가 필요하다.

`누락 후보군 원천`에서 `KIS 현재 마스터`를 고르면 오늘 장 마감 후 현재 KIS 마스터만 그 날짜로 저장한다. `KRX Open API 날짜별` 또는 `pykrx 날짜별`을 고르면 지정한 `누락 후보군 시작일`부터 최근 완료 거래일까지 저장되지 않은 날짜를 오래된 순서로 조회한다(한 번에 최대 120거래일). KRX Open API는 코스피·코스닥 종목기본정보와 일별매매정보를 함께 사용하며, 보통주·당일 정규 거래·당일 거래대금 기준으로 선정한다. `.env`의 `KRX_OPEN_API_KEY`와 네 서비스(유가증권·코스닥의 종목기본정보·일별매매정보) 이용 승인이 필요하다. pykrx는 `.env`의 `KRX_ID`, `KRX_PW`로 날짜별 상장 종목 목록과 당일 거래정보를 조회한다. 종목명은 pykrx의 현재·상장폐지 종목명 캐시를 사용하므로 당시 명칭과 다를 수 있다. 이름으로 구분 가능한 우선주·스팩과 당일 거래가 없거나 거래대금 기준에 미달한 종목을 제외한다. KIS의 관리종목·저유동성 상태·업종 분류 등을 동일하게 제공하지 않으므로 KIS 선정 결과와 다를 수 있다. 각 날짜의 출처·기준·차이를 보존하고 기존 스냅샷은 원천과 관계없이 덮어쓰지 않는다. KRX Open API의 401/403 거절은 키와 서비스별 승인을 확인하도록 표시한다.

두 UI는 최근 5거래일과 저장된 계좌·시장 후보 기록 중 가장 오래된 날짜부터 완료 거래일까지 누락된 선정 기록을 자동 확인하고, 첫 누락일을 시작일로 제안한다. 확인·수집 범위는 최근 180일·최대 120거래일로 제한한다. 이보다 오래된 날짜는 이 기능으로 수집할 수 없으며, 이미 저장된 날짜는 다시 쓰지 않는다.

시장 후보 화면의 `보고 싶은 거래일`은 그날 저장된 종목 목록·편입/제외·전략 조건 결과를 조회하고, 그 날짜까지 미계산된 전략 조건을 계산할 때 사용한다. 누락 자료 수집은 자동으로 찾은 첫 누락일부터 최근 완료 거래일까지 수행한다. KRX Open API·pykrx의 `수집 시작일 직접 바꾸기 · 고급`에서만 범위의 시작일을 직접 조정한다. 조회 날짜의 목록이 없으면 수집 범위에 그 날짜가 포함돼야 한다. 전략 조건 계산은 조회용이며 계좌 거래 기록을 바꾸지 않는다. 계좌에서 날짜별 종목 사용을 설정하면 다음 미처리 거래일부터 저장된 종목 목록을 새 매수 후보의 범위로 사용하고 그날의 조건을 다시 계산한다.

시장 후보 화면은 `1 시장 종목 선정 → 2 계좌 규칙으로 조건 계산 → 3 모의계좌에 이어 반영` 순서로 조작한다. 1단계는 기록된 선정 기준(기본값 당일 거래대금 10억원 이상, 종목 유형·거래 상태 등)을 보여준다. 2단계의 선별 종목 표는 선택 계좌의 RS·진입 규칙으로 평가한 모든 종목을 보여주며 조건 미통과 종목도 포함한다. 이 계산은 계좌 매매 기록을 변경하지 않는다. 3단계의 적용 설정은 분석 결과를 다시 필터링하는 기능이 아니라, 이후 일별 처리의 종목 목록을 날짜별 선정 기록으로 바꾼다. 정정 비교 계좌와 기본 계좌는 적용할 수 없으며, 기존 일반 계좌에서 적용 상태와 비활성화 이유를 확인할 수 있다. 저장 가격 처리와 계좌 후보 재계산은 고급 작업으로 접어 둔다.

편입·제외 표에는 선정 사유 코드를 한국어로 풀어 표시한다. 거래대금 선정 기준은 후보군 상단에 `10억원 이상`처럼 한 번만 표시한다. 편입 근거에는 이전 날짜의 상태를 반복하지 않고 선택 날짜의 거래대금만 `24억원가량`처럼 반올림해 표시한다. 제외 사유는 `거래대금 기준 미만`처럼 표시한다. 새 후보군을 저장할 때는 제외된 종목의 사유도 검증용 파일에 남긴다.

기존 일반 계좌에서 `이후 거래일부터 날짜별 종목 사용 설정`을 실행하면 계좌 ID와 과거 상태는 보존하고, 다음 미처리 거래일부터 날짜별 선정 기록을 사용한다. 가격·기준 유니버스는 계좌 전용 사본으로 남긴다. 제외된 보유 종목과 전일 매수 예정 종목은 관리용으로 계산하되 새 매수 후보에서는 제외한다. 새 편입 종목의 과거 일봉은 네이버 초기 이력으로 보충하고, 이후 새 거래일은 화면에서 선택한 원천으로 수집한다. 누락 날짜의 실제 후보군·산업 구성 기록이 없으면 현재 자료로 소급하지 않고 계좌 처리를 보류한다. 이 방식은 과거 계좌 성과를 다시 계산하지 않는다.

시장 후보 화면 아래의 `계좌 후보 재계산`, `일별 모의 처리`, `데이터 갱신 + 일별 처리`는 모두 그 화면의 `후보 기준일`을 사용한다. 계좌 후보 재계산은 선택 계좌에 저장된 종목·가격으로 해당 날짜의 신호만 다시 계산하고 계좌를 바꾸지 않는다. 날짜별 시장 후보군 저장만으로 이 분석의 종목 목록이 소급 변경되지는 않는다. 일별 모의 처리는 저장 가격으로 계좌를 처리하며, 데이터 갱신 + 일별 처리는 빠진 거래일 가격을 수집한 뒤 처리한다. 계좌 후보 재계산은 계좌의 현재 처리일에만 가능하다. 정정 재계산 계좌는 고정된 비교 결과이므로 이후 날짜를 보려면 원계좌로 이동한다.

시장 후보 화면 상단의 `저장된 시장 후보 계산`은 선택 날짜까지 저장됐지만 아직 계산되지 않은 시장 후보군을 날짜순으로 분석한다. 계좌의 매매·보유 상태는 바꾸지 않는다. 선택 계좌의 전략 설정과 저장 가격을 사용하고, 새 후보에 부족한 과거 일봉은 네이버에서 보충한다. 산업 구성은 해당 날짜까지 마지막으로 저장된 구성을 사용하므로 그 사이에 바뀐 구성은 정확히 복원할 수 없다. 결과는 각 날짜의 시장 후보 표에 표시하며 계좌 후보 재계산 결과와 구분한다. 첫 계산은 새 종목의 과거 일봉을 수집하므로 오래 걸릴 수 있다.

선정된 시장 종목 목록의 `산업`에는 후보 기준일까지 저장된 가장 최근 산업 구성의 이름을 표시한다. 목록 안에 산업 구성 저장일과 분류된 종목 수를 함께 표시한다. 해당 날짜 이전의 산업 기록이 없거나 구성에 없는 종목은 `산업 확인 불가`로 표시한다. 산업 정보는 화면 표시용으로 연결하며 저장된 후보군 선정 기록은 바꾸지 않는다.

화면의 표는 열 제목을 누를 때마다 오름차순, 내림차순, 정렬 해제 순서로 바뀐다. 정렬 해제는 해당 표의 기본 순서로 돌아간다. 숫자와 금액 단위는 값으로 비교하며, 값이 없는 행은 양쪽 정렬에서 마지막에 둔다. 선별 종목의 `종가 / 52주 고가`는 가격 규모가 다른 종목을 비교하는 정렬에 적합하지 않아 정렬 버튼 없이 표시한다. 여기서 52주 고가는 선택일을 제외한 직전 252거래일의 최고 고가다.

`셋업 무효화`의 50%는 주가가 절반으로 떨어진다는 뜻이 아니라 선행 파동 상승 폭의 절반 이상을 반납한다는 뜻이다. 100에서 150까지 오른 파동이면 오늘 저가가 125 아래로 가면 셋업이 무효화된다. 같은 날 저가 124 이후 종가 156으로 끝나고 직전 252거래일 고점이 155라면, 셋업 무효화와 52주 신고가 돌파가 동시에 참이다. 이 판정은 동일한 기준일의 저가·종가를 각각 비교한 결과로, 신고가 돌파가 무효화의 원인이라는 뜻이나 며칠간의 사후 상승을 뜻하지 않는다. 종목 상세에는 오늘 이전 베이스 저가를 쓴 준비 반납률과 오늘 저가를 포함한 반납률을 구분해 표시한다.

거래량 배수는 `기준일 하루 거래량 / 기준일을 제외한 직전 20거래일 평균 거래량`이다. 평균 10만 주에 기준일 15만 주이면 1.5배다. 화면의 설명에 현재 계좌의 `volume_multiple` 통과 기준을 표시한다. 셋업 조정 구간의 거래량 수축비와 장중 동시간대 거래량 배수와는 다르다.

## 운용 순서

접속하면 **운용 순서**가 먼저 열린다. 화면 위 1~4단계와 각 단계의 다음 버튼으로 진행하며, 매번 문서의 순서를 외울 필요가 없다.

1. **계좌·설정**: 왼쪽에서 사용할 계좌를 고르고 전략 요약을 확인한다. 처음 만들 때만 `새 계좌 만들기 · 전략 설정`을 펼친다. 저장하면 해당 계좌를 선택하고 2단계로 이동한다. 저장만으로 모의 처리를 실행하지 않는다.
2. **종가 처리**: 오른쪽 위 기준일을 확인한다. 당일 종가 처리는 16:10 이후다. 파동 셋업 계좌는 오늘 기준일에만 `① 오늘 산업 자료 갱신`을 직접 실행할 수 있고, 과거 기준일에서는 비활성화 이유를 표시한다. 산업 자료가 이미 준비됐다면 ①을 건너뛰어도 된다. `② 일봉 수집 + 미처리 거래일 모의 처리`는 누락 일봉을 채우고 선택 날짜까지의 미처리 거래일을 순서대로 처리한다. 작업 상태·실패 사유도 이 화면에 남는다. 이미 처리한 날짜는 재실행 대신 결과 확인을 안내한다. 주말·미확정 날짜·산업 자료 누락·설정 불일치 시 이유를 표시하고 실행을 막는다. 휴장 여부의 최종 확인은 기존 데이터 수집 엔진이 맡는다.
3. **결과 확인**: 저장 기준일, 진입 신호, 보유·다음 시가 대기를 확인한다. 신호가 0건이어도 정상일 수 있다. 첫 계좌 처리는 선택 날짜의 종가를 출발점으로 만들며 당일 장중 매수를 소급 처리하지 않는다. 세부 종목·청산·체결은 상세 화면에서 볼 수 있다.
4. **운용 순서 4 · 장중 관측**: 종목과 감시 범위·거래일을 선택하고 `자료 준비 및 계획 생성`을 누른다. KRX 달력의 직전 거래일을 기준으로 저장된 후보를 사용하거나 일봉과 비교 자료를 확보해 후보를 계산한다. 전체 산업 범위는 해당 날짜의 산업 구성 자료가 필요하다. 보유 종목과 손절선은 계좌 처리일이 후보 기준일과 같을 때 반영한다. 저장된 계획은 감시 거래일 KRX 정규장 09:00~15:30 또는 NXT 애프터마켓 15:40~20:00에 ON할 수 있다. 기본 관측은 20:00까지 이어지고 OFF로 일찍 중단할 수 있다. 관측 종료 후 16:10 이후 정규장 거래량 이력을 누적하고, 해당 거래일 종가 데이터 확보 후 기준일을 맞추어 대조한다.

다음 날에도 같은 계좌를 선택해 2단계부터 진행한다. 설정을 바꾸어 비교할 때는 새 계좌를 만든다. 산업 갱신은 현재 시점 수집이며 과거 날짜 구성을 재현하지 않는다. 같은 계좌에 UI와 CLI 처리를 동시에 실행하지 않는다. 장마감 전에 접속하면 최근 완료 평일을 기본 기준일로 안내한다. 실제 거래소 휴장일을 미리 판정하는 달력은 아니다.

조회는 증권사 API를 호출하지 않는다. 가격·산업 갱신과 관측 ON은 명시적으로 실행할 때 외부 API를 호출한다. 처리 작업은 한 번에 하나만 실행되며 장중 OFF는 별도로 제어한다.

종가 계획, 장중 잠정 상태, 모의 체결을 구분한다. OFF·자료 없음은 미확인이며 신호 0건이나 조건 미통과로 간주하지 않는다. 종료되거나 오래된 장중 이벤트는 현재 진입 신호로 알리지 않는다. 브라우저 알림은 허용한 뒤 페이지가 열려 있는 동안 새 진입 계획·RS 청산·장중 진입/손절 접촉을 알려준다. 최초 조회한 과거 기록은 알리지 않는다.

화면의 조건 설명은 파란 안내 카드로, 처리 완료는 녹색으로, 실패·진행 차단은 붉은 강조 카드로 구분한다. 오른쪽 아래 오류 알림은 직접 닫기 전까지 유지하며 화면 읽기 도구에는 오류로 알린다. 정상 알림은 10초 뒤 사라진다. 이전 실패 기록과 현재 실패도 운용 순서 화면에서 별도 상태로 표시한다.

## 자동화와 현재 범위

브라우저는 조작·조회 화면이고 Python 엔진이 처리한다. 브라우저를 닫아도 UI 서버가 살아 있으면 접수한 작업이 진행된다. 시작한 장중 관측 프로세스는 지정 시간까지 독립 실행되며 OFF로 중지할 수 있다. PC 절전·종료 시 정상 수집을 기대할 수 없다.

이후 Windows 작업 스케줄러나 백그라운드 운용 관리자를 연결할 수 있다. **이번 구현에 예약 실행 등록, 자동 재시작, 증권사 주문·잔고 동기화는 포함하지 않는다.** 서버 재시작 시 미완료 작업은 중단으로 표시하고 자동 재실행하지 않는다. 계좌 처리일을 확인한 뒤 수동 재실행한다.

키는 기존 `.env`를 엔진에서 읽으며 브라우저에 보내거나 화면에서 편집하지 않는다. 새 설정·분석·작업·장중 기록은 `outputs/ui/`에 저장된다. 기존 계좌 모의 처리는 기존 상태 경로를 사용한다. 서버는 루프백 주소에만 연결되며 쿠키·요청 토큰·동일 출처 검사로 보호한다. 외부 공개 서버 배포용은 아니다.

## 과거 데이터 정정으로 실패한 경우

운용 순서 2단계의 정정 복구 영역에서 변경 전후를 대조하고, 이전 결정을 보존해 계속 운용하거나 별도 수정 데이터 재계산 계좌를 만들 수 있다. 가격 기준 변경·행 누락·원본 부족 시 복구를 보류한다. 수집 완료 후 실패와 실제 작업 중을 구분해 표시한다. 정책·보존 파일·확인 절차는 [DATA_REVISIONS.md](DATA_REVISIONS.md)를 따른다.

## 화면 연결이 끊기거나 서버를 다시 시작한 경우

브라우저 응답 연결 중단은 백그라운드 작업 실패와 별개다. 재접속 후 계좌 처리일과 실행 작업의 최신 저장 상태를 확인한다. 서버는 연결이 끊긴 응답에 다시 오류 응답을 보내지 않는다. 다른 UI 서버에서 실행 중인 신규 작업은 OS 잠금으로 확인하며 중단으로 바꾸지 않는다. 완료 기록은 화면에서 주기적으로 다시 읽는다. 실행자가 실제 종료된 작업은 중단으로 표시하고 자동 재실행하지 않는다. 실행자 정보가 없는 이전 버전의 미완료 작업은 실행 여부 미확인으로 표시하며 다른 서버가 살아 있을 가능성을 남긴다. 같은 공유 작업 폴더에서 여러 UI 서버가 동시에 처리 작업을 시작하는 것도 막는다. 이전 실패 뒤 같은 날짜의 처리 완료가 확인되면 과거 실패 이력으로 구분한다.

정정 반영 완료 후 대조 표는 자동으로 접히고 `정정 반영 완료 · 변경 이력 N건 보기`로 표시된다. 펼치면 이전 값·정정 값과 보존 근거를 다시 확인할 수 있다. 완료한 건의 검토 확인란·계속 운용 버튼은 숨기며, 새 정정 보고서는 다시 펼쳐 검토하도록 표시한다. 주기적 상태 갱신은 사용자가 펼치거나 접은 상태를 바꾸지 않는다.


## Streamlit · 모의계좌 운용 작업대

기존 UI는 그대로 유지한다. Streamlit은 같은 `Operations` 서비스와 전략 엔진을 호출하며,
선택·검색·화면 재실행으로 분석이나 모의 처리를 자동 실행하지 않는다.

```bash
python -m pip install -e '.[streamlit]'
streamlit run streamlit_app.py
```

Paper Blue 테마로 `오늘의 운용`을 먼저 연다. 사이드바에서 계좌를 바꾸면 이 화면으로 돌아오며,
거래소 달력과 현재 시각으로 목표 거래일을 제안한다. 화면 맨 위의 안내 버튼을 먼저 누른다.
기본 메뉴는 `오늘의 운용`, `시장 후보`, `운용 기록`이다. 시장 후보에서 거래일을 고르고 파동 그림이나 필터로 종목을 좁힌다. 카드의 종목 또는 표의 행을 누르면 표 아래에서 같은 날짜의 차트와 조건 판정을 확인할 수 있다. 계좌 선택 옆의 `설정`에서 전략과 날짜별 후보군 사용 여부를 확인한다.
운용 기록에서 계좌 처리일을 고르면 당시 계획·보유와 다음 처리일의 후보 종목 주문을 볼 수 있다. 날짜·자료 원천은 필요할 때만
사이드바의 고급 설정에서 바꾼다. 마지막 처리일·목표일·남은 거래일은 주요 버튼 아래에서 확인한다.
장 마감 후 `필요한 자료 준비·종가 처리`를 누르면 날짜별 후보군을 쓰는 계좌의 누락 종목 목록,
산업 자료, 일봉을 채우고 미처리 거래일을 순서대로 모의계좌에 반영한다. 과거 종목 목록은
설정된 KRX Open API 키를 우선 사용하고 없으면 pykrx 로그인 정보를 사용한다. 오늘 목록은
16:10 이후 KIS 현재 마스터를 사용한다. 조회 원천이 없거나 거절되면 원인을 표시하고 계좌 기록을 보존한다.
파동 셋업 계좌의 오늘 산업 자료 다시 수집과 저장 가격 처리는 `자료 상태와 수동 작업`을 펼쳐 사용한다.
전체 거래일 진행과 종목별 수집 단계를 표시한다. 완료 후 같은 화면에서 후보·수량·계획 위험을 확인하고, 중단 후
남은 거래일을 이어 처리한다.
`날짜별 시장 후보`는 KIS 현재 마스터 또는 KRX Open API·pykrx 날짜별 자료로
후보군을 저장하고 계좌 규칙으로 분석한다. 계좌 설정에서 날짜별 후보군 사용을 켜면 다음 미처리 거래일부터 적용한다.
날짜별 시장 후보의 종목 목록 저장과 오늘의 운용의 OHLCV 일봉 갱신은 별도 작업이다.
처리할 거래일의 종목 목록이 빠져 있으면 `오늘의 운용`의 종가 처리 작업 안에서 자동 저장한다.
`날짜별 시장 후보`는 과거 후보군을 별도로 확인하거나 원천·시작일을 직접 지정할 때 사용한다.
정규장·NXT 애프터마켓에는 직전 완료 거래일 처리가 끝난 파동 셋업 계좌에서 저장된 계획이나
감시 대상을 재사용해 `장중 관측 시작`을 안내한다. 대상이 전혀 없으면 처음 한 번 종목을 선택한다.
관측은 사용자가 버튼으로 시작하며, 장 마감 후 종가 처리는 별도로 실행한다. 예약·무인 자동 실행은 없다.
종목 탐색에서는 산업·RS·신호·거래량·셋업·52주 신고가 필터와 표 아래 최대 15개월 캔들·선
차트를 제공한다. 차트 안의 기간 버튼·확대·이동으로 범위를 바꾸고, 봉을 가리키면 좌측 상단에
OHLCV·ATR·ATR 대비 변동 배수를 표시한다. 거래량 옆의 배수는 해당일 거래량을 직전 20거래일 평균 거래량으로 나눈 값이다.
20거래일 기록이 없거나 평균이 0이면 배수는 `자료 없음`으로 표시한다. 거래량은 가격과 분리된 영역에 표시한다.
Lightweight Charts 라이브러리는 프로젝트에 포함해 제공하며 차트 아래에 TradingView 출처를 표시한다.
`장중 관측`은 거래 시간에는 오늘 거래일을 자동으로 사용해 대상·범위를 선택하고 한 번에
계획 준비와 관측 ON을 실행한다. 관측 시간 밖에는 다음 거래일 계획만 저장할 수 있다.
기본 감시 범위는 `입력 종목만`이고 `전체 산업 포함`을 고르면 예상 KIS 구독 수를 함께 보여준다.
관측 OFF는 별도로 제공한다. 현재 선택 종목의 오늘 실행 결과와 KIS 거절 사유를 먼저 보여주며,
관측 시작 요청의 `starting`은 연결 성공으로 표시하지 않는다. 이후 실행 결과에서 구독 승인 수와
연결 실패 사유를 확인한다.
다른 종목의 이전 관측 기록·시간대별 근거·종가 대조·거래량 누적·동시간 기준 생성은 접힌
보조 영역에서 확인한다. 종가 대조는 선택한 관측 기록의 거래일을 사용하며 해당 거래일
16:10 전에는 실행할 수 없다. 계좌 이름·보관 상태는
`전략·설정`, 과거 입력 정정과 위험 기록은 `정정·검증`에서 확인한다.
장중 관측 대상은 선택 계좌의 종목명이나 코드로 검색해 고른다. 정정 내역도 종목명·코드로
찾고, 이름이 여러 코드에 걸리면 종목을 직접 선택한다. 표에는 저장된 종목명이 있으면 코드와
함께 표시한다. 검색은 저장된 계좌 종목 목록과 KIS 마스터를 사용하므로 입력할 때마다 API를
호출하지 않으며, 마스터에 없는 과거 코드는 코드로 검색할 수 있다.
전략 설정은 검증되는 JSON 편집을 제공한다. 브라우저 시스템 알림은 포함하지 않는다.
최근 작업은 해당 화면에서 버튼과 같은 이름으로 진행 단계와 완료 건수를 3초마다 갱신한다.
다른 화면에서도 작업 상태를 확인할 수 있다. 완료 시 분석·계좌 화면을 자동으로 다시 읽고,
이전 작업은 접힌 기록에서 확인한다. 과거 종가 대조 실패는 새 장중 관측이나 오늘의 종가 처리
오류처럼 화면 상단에 반복 표시하지 않는다.

### 실행 권한과 키

`UI_PASSWORD`가 없으면 조회 모드다. 로컬에서는 기존 `.env`에
`UI_PASSWORD=직접-정한-긴-비밀번호`를 추가하거나 `.streamlit/secrets.toml`에
다음을 설정하고 앱에서 로그인한다. 두 파일 모두 Git에서 제외한다.
Streamlit Secrets, 프로세스 환경변수, `.env` 순서로 값을 선택한다.

```toml
UI_PASSWORD = "충분히-긴-개인용-비밀번호"
# 필요한 증권사의 실제 값은 로컬 또는 Cloud Secrets에서만 입력한다.
# KIS_ENV = "paper"
# KIS_APP_KEY = "..."
# KIS_APP_SECRET = "..."
# KIWOOM_ENV = "paper"
# KIWOOM_APP_KEY = "..."
# KIWOOM_SECRET_KEY = "..."
# KRX_ID = "..."
# KRX_PW = "..."
# KRX_OPEN_API_KEY = "..."
```

Community Cloud에는 로컬 `.env` 파일이 배포되지 않는다. 앱 설정의 Secrets에
같은 `UI_PASSWORD = "..."` 형식으로 입력한다. 키도 필요한 항목만 Secrets에
입력하며 저장소에 비밀번호나 키 파일을 올리지 않는다.

로그인은 개인용 단일 운용자 기준이며 다중 사용자별 계좌 격리는 제공하지 않는다.
로그인 후 같은 브라우저에서 F5로 새로고침해도 서명된 쿠키로 권한을 복원한다. 쿠키에는 비밀번호를 저장하지 않으며 12시간 뒤 만료된다. 서명 키는 Git에서 제외한 `outputs/ui/auth-secret.bin`에 보관해 앱 코드 재로드와 서버 재시작 때도 유지한다. `로그아웃`을 누르거나 비밀번호를 바꾸면 다시 로그인해야 한다. 로컬 저장소가 초기화되면 서명 키도 바뀌므로 다시 로그인해야 한다.
비밀번호가 없더라도 조회 화면은 열리므로 계좌 정보 비공개가 필요하면 앱 접근 자체를 제한한다.
Streamlit 관리자는 프로세스별로 공유된다. 기존 UI·CLI·다른 Streamlit 프로세스를
같은 계좌에 동시에 실행하지 않는다. Streamlit은 기존 엔진의 작업 보호를 재사용하며 별도의 분산 작업 큐는 추가하지 않았다.

개발 중 Python 코드나 UI 설정을 수정하면 실행 중인 Streamlit 프로세스가 새 화면 코드와
이전 `Operations` 객체를 함께 사용할 수 있다. 앱은 소스 변경을 감지하면 새 작업을 막고
실행 중 작업이 있는지 표시한다. 작업이 끝난 뒤 Streamlit 서버를 한 번 다시 시작하면
새 코드 전체가 같은 버전으로 로드된다. 브라우저 새로고침만으로 코드 변경을 적용하지 않는다.

### Streamlit Community Cloud

GitHub에 변경을 올린 뒤 Community Cloud에서 리포지터리와 브랜치를 선택하고
진입 파일을 `streamlit_app.py`로 지정한다. 루트 `requirements.txt`로 의존성을 설치하며,
키와 비밀번호는 앱의 Secrets에 입력한다. 개인정보가 있으면 앱의 접근 범위도 제한한다.

Cloud에서 계좌를 보존하려면 비공개 Cloudflare R2 Standard 버킷을 준비한다.
R2의 API Tokens에서 해당 버킷 하나에만 **Object Read & Write** 권한을 주고 발급한
S3 자격 증명을 사용한다. Streamlit 앱 **Settings → Secrets**에서 기존 최상위 설정
아래에 다음 TOML 섹션을 추가한다.

```toml
[r2]
account_id = "Cloudflare Account ID (32자리)"
bucket = "trendfollow-data"
access_key_id = "R2 Access Key ID"
secret_access_key = "R2 Secret Access Key"
```

사이드바 **배포·저장 안내**에서 연결된 버킷을 확인할 수 있다. 첫 연결 시 빈 버킷에는
현재 계좌와 자료를 저장하고, 기존 백업이 있으면 계좌 목록을 열기 전에 복원한다.
계좌 생성·이름 변경·관심 종목·전략 설정 변경과 거래일별 종가 처리를 자동 저장한다.
복원에는 보유·현금·대기 주문, 거래일별 판단과 체결 기록, 후보군·가격·산업 자료가 포함된다.
인증 비밀, 프로세스 잠금, 실시간 장중 체결 스트림과 작업 로그는 백업 대상에서 제외한다.
연결 실패 시 버킷 이름과 키 권한을 확인한다. 저장 실패 후에는 앱 재부팅 전에
**R2에 다시 저장**으로 재시도한다. 동일 버킷은 한 앱의 운용 데이터 전용으로 사용한다.
버킷의 `trendfollow/v1/` 안에는 내용별로 중복을 제거한 파일과 최신 복원 목록이 저장된다.
이전 파일 버전도 용량에 포함되므로 사용량을 확인하고, 이 경로에는 자동 만료를 설정하지 않는다.

R2 설정이 없으면 로컬 방식으로 동작한다. Cloud의 로컬 파일은 재시작·재배포 시 사라질 수 있다. 저장소에 포함되지 않은
시세·유니버스가 없으면 준비 필요 상태로 표시한다. `data/market/universe.csv`와
필요한 가격·산업 데이터의 공급도 별도로 준비해야 한다. `산업 자료 갱신`은 원본 시장
유니버스가 필요하며 최초 시장 유니버스 수집을 대신하지 않는다.

장중 관측 ON/OFF는 연결되어 있지만 Cloud의 앱 휴면 중 지속 실행은 보장되지 않는다.
Community Cloud는 Python·외부 패키지 의존성 설치와 저장소에 포함된 정적 차트 파일을 지원한다.
프론트엔드 빌드를 Cloud 실행 시에 해야 한다는 가정은 두지 않는다. 현재 운용 화면은 기본 Streamlit
위젯과 주기 갱신 Fragment를 사용하며 별도 UI 패키지를 요구하지 않는다. Cloud의 자원 제한과
무접속 휴면 때문에 장시간 수집·상시 관측의 운영 안정성은 별도로 검증해야 한다.
