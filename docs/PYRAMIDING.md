# 추가매수 모의 체결과 합산 위험 관리

최초 진입 → 3R 달성 → 새 셋업 검토 → 다음 거래일 추가매수 모의 체결을 연결한다. 증권사 주문 API는 사용하지 않는다. 기본은 OFF이며 기존 모의계좌를 자동 전환하지 않는다.

## 실행 조건

- `rules.pyramiding_enabled: true`, `pyramiding_review_enabled: true`, `entry_method: setup`, `initial_stop_reference: entry_fill`이 필요하다.
- `pyramiding_max_additions`는 0~3이며 기본 3이다. 최초 진입을 포함하면 최대 4차 매수다. 성공적으로 체결한 추가매수만 세며 취소·미체결은 세지 않는다.
- 기존 검토 조건인 최초 3R 종가 달성, 현재도 3R 이상, 달성일 이후 새 고점·조정·재돌파, 선택한 RS·주봉 추세·거래량·산업 동반 상승 조건을 재사용한다. 새로운 고정 조정 기간은 추가하지 않는다.
- 서로 다른 셋업에서 한 번씩만 추가한다. 검토·대기·체결 식별값을 보존해 같은 셋업을 다시 매수하지 않는다. 취소된 셋업도 재시도하지 않으며 다음 새 셋업을 기다린다.
- 추가매수 가격은 직전 체결가보다 높아야 한다. 물타기는 허용하지 않는다. 시장 유닛 옵션을 사용하는 경우 신호일에 확정된 상한과 현재 거래 성과 유닛의 최솟값을 적용한다.

## 공통 손절선

추가분 손절가는 최초 진입과 동일한 고정·ATR·자동 전환 정책으로 계산한다. ATR은 신호일 값으로 고정하고, 다음 거래일 시가에 진입 슬리피지를 반영한 모의 체결가에서 다시 계산한다.

새 손절선이 기존 공통 손절선보다 **엄격히 높아야** 추가매수를 허용한다. 낮거나 같으면 매수하지 않는다. 수량을 늘리려고 손절선을 임의로 당기지 않는다. 실제 모의 체결이 성공하면 기존분과 추가분 전체에 새 공통 손절선을 적용한다. 취소·수량 0이면 추가매수 때문에 손절선을 바꾸지 않는다. 기존 추적 손절은 독립적으로 계속 적용한다.

개별 차수의 최초 손절가·진입가·수량·위험은 기록으로 남기지만 실제 청산은 공통 손절선으로 전량 처리한다. 최초 진입의 `entry_price`, `initial_quantity`, `initial_risk`, `target_3r`는 고정하고, `average_entry_price`, `entry_total`, `quantity`, `total_committed_risk`, `lots`, `addition_count`를 별도로 갱신한다.

3R에서 익절하지 않는다. 최초 3R 성공과 점진 유닛 증가는 종목의 한 보유 구간에서 한 번만 발생한다. 추가분의 상승을 새로운 3R 성공으로 중복 계산하지 않는다.

## 2% 상한과 운용 예산

`limits.max_trade_risk`는 기본 1%를 유지하며 **2% 초과 설정을 거절**한다. 이 검증은 추가매수 OFF의 최초 진입에도 적용한다. 2%는 매번 사용할 권장 비율이 아니라 넘을 수 없는 계획 위험 상한이다. 새 모의 체결 모드에서는 같은 종목의 기존·추가분 합계를 이 설정 이하로 제한하므로 기본 종목 합산 한도도 1%다.

순자산 E는 현재 현금과 알려진 시세로 평가한 보유액의 합이다. 최초 입금액에 고정하지 않는다. 회당 위험 예산은 `E × max_trade_risk × 유효 유닛 / max_units`다. 기본 최대 5유닛 중 2유닛이면 E의 0.4%이며, 기존분 위험이 이미 종목 한도를 사용하면 추가 수량은 더 작아진다.

합산 위험은 매입원가 대비 손익이 아니라 **현재 평가액에서 공통 손절가까지의 되돌림 위험**이다. 기존 평가이익을 음수 위험으로 계산해 추가분 위험과 상쇄하지 않는다.

- 기존분 주당 위험: `max(0, 현재가 − 손절가 × (1 − 청산 슬리피지) × (1 − 청산 비용률))`.
- 추가분 주당 위험: `모의 체결가 × (1 + 진입 비용률) − 손절가 × (1 − 청산 슬리피지) × (1 − 청산 비용률)`.
- 새 공통 손절선에서의 기존분 위험 + 추가분 위험 ≤ 종목 합산 한도.
- 다른 보유 종목까지 합친 위험 ≤ `limits.total_risk`(기본 4%). 종목별 2%와 계좌 전체 4%는 서로 다른 한도다.

최초·추가 매수 후보는 같은 수량 배분 단계에서 RS 순서(동률은 종목코드 순서)로 현금·종목 비중·산업 비중·계좌 위험·거래대금 한도를 공유한다. 먼저 체결한 후보에 쓴 예산을 다음 후보가 다시 쓰지 못한다. 신규 체결 비용으로 순자산이 줄어드는 효과도 위험 한도에 반영한다. 추가매수에 따른 손절 상향으로 줄어드는 위험은 체결이 성공하는 경우에만 배분 장부에 반영한다.

예를 들어 비용 전 순자산 1,000만 원, 기존 100주, 현재가 13,000원, 기존 손절가 12,000원이라고 하자. 새 기준으로 손절선을 12,500원까지 올릴 수 있다면 기존분 위험은 5만 원이다. 2유닛 추가분 예산 4만 원, 주당 위험 500원이므로 다른 한도에 여유가 있을 때 80주를 추가할 수 있다. 합산 위험은 9만 원으로 기본 1% 한도인 10만 원 안에 있다. 실제 계산에는 비용·슬리피지가 포함된다.

2%는 주문 시점의 **계획** 손실 한도이며 실제 손실을 보장하지 않는다. 갭·거래정지·체결 차이로 초과할 수 있다. 보유 중 가격 변화로 한도를 넘으면 위험 기록에 표시하고 새 매수 배분을 제한한다. 이 사유만으로 손절선을 임의로 올리거나 보유분을 강제 분할 매도하는 규칙은 추가하지 않았다.

## 다음 거래일 검증과 청산 우선

종가 검토 후보는 모의 대기 목록에 `order_intent: add`로 저장한다. 다음 시가에서 청산 대기, 기존 포지션 소멸, 5% 초과 갭 상승, 거래 불가, 신호일 계획 손절가 이하 시가, 현재 3R 미달, 직전 매수가 이하, 추가 횟수, 동일 셋업 체결 여부, 손절 상향, 합산 예산을 다시 확인한다.

청산이 우선이다. 기존분이 갭 손절·RS 약화로 청산되면 대기 중 추가매수로 새 포지션을 만들지 않는다. 보유 종목의 현재 시가가 없어 합산 평가가 불확실하면 새 매수 전체를 보류한다. 단일 가격 봉은 체결을 가정하지 않는다. 장중 저가에 공통 손절이 닿으면 해당 종목 전체 수량을 기존 모의 규칙으로 청산한다.

## 설정과 실행

- 기존 검토 전용 설정: `examples/config-pyramiding-review.json`.
- 추가매수 모의 체결 설정: `examples/config-pyramiding.json`. 자동 전환 초기 손절, RS 순위·셋업·산업 동반 상승·RS 약화 청산을 사용하며 15% 폭 제한은 OFF다.

새 모의계좌 시작 예시(기존 계좌 파일을 사용하지 않는다):

```powershell
python -m trendfollow paper --prices data/market/history/prices.csv --universe data/industries/universe.csv --as-of 2026-11-06 --config examples/config-pyramiding.json --state outputs/paper-pyramiding/state.json
```

첫 실행은 종가 계획의 시작점이며 과거부터 매수한 것으로 채우지 않는다. 이후 `daily` 또는 `paper`에 같은 설정과 상태 파일을 전달한다. 이번 구현 중 실측 계좌를 새로 시작하거나 기존 세 계좌를 바꾸지 않았다.

과거 비교는 **같은 추가매수 설정**에서 `backtest --pyramiding on`과 `--pyramiding off`를 각각 실행하고 나머지 입력·기간·자금은 같게 유지한다. 두 명시적 비교 모드는 최초 진입 수량 계산에도 동일한 합산 위험 계산기를 사용해, 추가매수 전부터 수량이 달라지는 효과를 배제한다. 기존 검토 전용 설정 자체의 기본 동작은 보존한다. 산업 동료 이력이 없는 과거 구간의 전체 전략 백테스트는 실행하지 않는다. 먼저 고정 유닛 결과를 비교한 뒤 점진 유닛의 영향도 확인한다.

## 결과 기록

- `pyramiding-review.csv`: 종가 후보·보류 사유. 실행 모드의 통과 후보는 `scheduled_for_next_open`이며 종가에서 수량을 확정하지 않는다.
- `orders.csv`: 추가매수 의도·체결/거절 사유·차수·수량·공통 손절 전후·합산 위험과 한도. 증권사 주문 내역이 아니다.
- `campaign-lots.csv`: 최초 매수와 각 추가분의 진입 비용·수량·신호일 ATR·초기 위험·셋업. 나중에 전량 청산해도 기록이 남는다.
- `campaign-risk.csv`: 종가 평가 기준 종목·계좌 위험, 운용 한도/2% 초과 여부, 시세 누락 여부.
- `trades.csv`: 전체 수량·전체 비용으로 계산한 손익, 최초 위험 기준 `r_multiple`, 투입한 각 차수의 최초 위험 합계 기준 `r_multiple_total_committed_risk`를 구분한다.

실제 장중 추가매수 관측·실계좌 주문·시간 청산은 이번 범위에 포함하지 않는다. 충분한 과거 산업 이력과 전향적 모의운용을 통한 성과 검증이 남아 있으며 추가매수의 수익성 우위는 아직 확인하지 않았다.
